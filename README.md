# Закулисье Майнкрафта Вики — экспертный портал

Статический фронтенд + API на Cloudflare Pages Functions + база Cloudflare D1.

## Что умеет сайт

- Аккаунты: регистрация по нику и паролю (без почты), вход, смена пароля, удаление аккаунта.
- Профили пользователей и карточки авторов (аватар, описание, статистика), редактирование своего профиля.
- Пользователь может создать **свою карточку автора** и править её; админ правит любые и может привязать карточку к аккаунту.
- Рецензии только от зарегистрированных, до **10 000 символов**, публикуются после модерации.
- Поиск по статьям, авторам и пользователям (в шапке и на каждой странице списка).
- Админ-режим по паролю: модерация, баны, сброс пароля, удаление аккаунтов, экспорт/импорт JSON.

## Структура

```
public/                      сайт (Build output directory = public)
functions/api/[[route]].js   API (маршруты)
lib/common.js, lib/auth.js   общий код API (валидация, пароли, сессии)
schema.sql                   схема для НОВОЙ пустой базы
migrations/002_accounts.sql  обновление уже работающей базы (версия 1 -> 2)
```

## Обновление уже работающего сайта

1. D1 → ваша база → **Console** → выполните `migrations/002_accounts.sql` **один раз** (если консоль не принимает всё сразу, по одной команде).
2. Залейте файлы в репозиторий GitHub (папки `functions`, `lib`, `public`, `migrations`), дождитесь деплоя.
3. Старые рецензии и авторы сохраняются. Новая база — вместо миграции выполните `schema.sql`.

## Настройка Cloudflare (первый запуск)

- Build command — пусто, Build output directory — `public`.
- Settings → Bindings: D1 с именем **`DB`**.
- Для загрузки аватарок создайте R2 bucket и подключите его в Pages → Settings → Bindings как **R2 bucket** с переменной **`AVATARS`**. Если привязка не настроена, сайт продолжит работать, но загрузка файлов будет недоступна.
- Settings → Variables and secrets: секрет **`ADMIN_PASSWORD`** (от 12 символов).
- Необязательно: `TURNSTILE_SECRET` + `TURNSTILE_SITE_KEY` (капча при регистрации).
- Необязательно: `PBKDF2_ITERATIONS` (10000–100000, по умолчанию 100000). Если на бесплатном плане регистрация/вход падают с ошибкой лимита CPU, поставьте 50000 или 20000.
- После любого изменения привязок/секретов — новый деплой.

## Безопасность

- Пароли хранятся только как PBKDF2-SHA256 с солью; сессии — случайные токены в HttpOnly-cookie (в базе только их хеш).
- Все изменения проверяются на сервере; проверка Origin против CSRF; лимиты на вход, регистрацию и отправку рецензий.
- Пользовательский текст выводится только как текст (без innerHTML); аватары — только https-ссылки; строгая CSP в `public/_headers`.
- Пароль админа и пользователей не хранится в репозитории.
- Почты нет, поэтому забытый пароль пользователю сбрасывает администратор (на странице пользователя → «Сбросить пароль»).
- Экспорт JSON содержит авторов и рецензии, но не аккаунты и пароли. Для полного бэкапа базы используйте D1 Time Travel.

## Локальный запуск

```
npx wrangler d1 execute zmv-wiki --local --file=schema.sql
npx wrangler pages dev public --d1=DB --binding ADMIN_PASSWORD=long-local-password
```
